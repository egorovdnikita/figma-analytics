# Подключение Google: получить Client ID и Client Secret

Figma Analytics работает напрямую с вашим аккаунтом Google, без промежуточного сервера. Поэтому нужен
собственный OAuth-клиент — это бесплатно и занимает 5–7 минут.

## 1. Проект в Google Cloud

1. Откройте [console.cloud.google.com](https://console.cloud.google.com/).
2. Вверху нажмите на переключатель проектов → **New project**. Название любое, например `figma-analytics`.
3. Дождитесь создания и выберите проект.

## 2. Включить Google Calendar API

1. Меню → **APIs & Services → Library**.
2. Найдите **Google Calendar API** → **Enable**.

## 3. Настроить экран согласия

1. **APIs & Services → OAuth consent screen**.
2. User Type: **External** (если у вас личный Gmail) → **Create**.
3. Заполните обязательные поля: название приложения (`Figma Analytics`), почта поддержки, контактная почта.
4. На шаге **Scopes** ничего добавлять не нужно — приложение запросит доступ при входе.
5. На шаге **Test users** добавьте свой Gmail-адрес. Пока приложение в статусе Testing, входить
   могут только пользователи из этого списка.
6. Сохраните. Публиковать приложение (**Publish app**) нужно только если сборку будут ставить
   другие люди — см. раздел [«Раздать сборку другим людям»](#раздать-сборку-другим-людям) ниже.

> В режиме Testing refresh-токен живёт 7 дней, после чего Figma Analytics попросит войти заново.

## 4. Создать OAuth-клиент

1. **APIs & Services → Credentials → Create credentials → OAuth client ID**.
2. Application type: **Desktop app**.
3. Название любое → **Create**.
4. Скопируйте **Client ID** и **Client Secret**.

Redirect URI вручную указывать не нужно: для типа Desktop app Google разрешает loopback-адреса
(`http://127.0.0.1:<порт>`), а Figma Analytics поднимает локальный сервер на свободном порту.

## 5. Передать ключи в приложение

Есть два способа — любой на выбор.

**Через интерфейс.** Запустите Figma Analytics, вставьте Client ID и Client Secret на первом экране.
Значения сохранятся в файл `credentials.json` в папке пользовательских данных приложения.

**Через `.env` при сборке.** В корне репозитория:

```bash
cp .env.example .env
```

```
GOOGLE_CLIENT_ID=1234567890-abcdef.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-...
```

Значения вшиваются в сборку, и экран ввода ключей не показывается.

## Раздать сборку другим людям

Чтобы человек со стороны мог поставить `.dmg`/`.exe` и войти своим Google-аккаунтом без того,
чтобы заводить собственный OAuth-клиент, нужны два действия — одно ваше в консоли Google,
второе техническое (зашить ваши ключи в сборку).

### 1. Опубликовать OAuth consent screen (делаете сами, я не могу это нажать за вас)

1. [console.cloud.google.com](https://console.cloud.google.com/) → ваш проект →
   **APIs & Services → OAuth consent screen**.
2. Кнопка **Publish app** → подтвердить.
3. Статус сменится с **Testing** на **In production**. Список Test users после этого не нужен —
   войти сможет любой Google-аккаунт.

Что это даёт и чего не даёт:

- Любой человек сможет пройти вход. При первом входе Google покажет экран
  **«Google hasn't verified this app»** — пользователю нужно нажать
  **Advanced → Go to Figma Analytics (unsafe)**. Это лишний клик, не блокировка.
- У неверифицированного опубликованного приложения есть мягкий потолок Google —
  ориентировочно 100 аккаунтов, прошедших согласие. Для раздачи друзьям/коллегам
  этого с большим запасом достаточно; если понадобится больше — см. верификацию ниже.
- Верификация не нужна, чтобы приложение просто работало.

### 2. Зашить ключи в сборку, которую вы раздаёте

Если собираете `.dmg`/`.exe` локально — положите `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`
в `.env` (см. раздел «Передать ключи в приложение» выше) перед `npm run dist:mac` /
`npm run dist:win`. Без этого каждый, кто поставит сборку, увидит экран ввода своих ключей —
тоже рабочий вариант, просто добавляет 5–7 минут настройки на стороне каждого пользователя.

Если собираете через GitHub Actions (workflow `build.yml`) — добавьте те же значения как секреты
репозитория: **Settings → Secrets and variables → Actions → New repository secret** →
`GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`. Workflow уже их подхватывает.

### Нужна ли полная верификация Google

Только если ожидаете больше ~100 реальных пользователей или хотите убрать экран
«не верифицировано». Это отдельный процесс: политика конфиденциальности, сайт приложения,
иногда демо-видео, и ревью может занять от нескольких дней до пары недель — для личного проекта
обычно избыточно.

## Что запрашивает приложение

| Разрешение | Зачем |
| --- | --- |
| `openid`, `email`, `profile` | Имя, почта и аватар для профиля |
| `.../auth/calendar` | Список календарей, их настройки и цвета |
| `.../auth/calendar.events` | Чтение, создание, изменение и удаление событий |

Access- и refresh-токены хранятся локально и шифруются через `safeStorage` Electron
(Keychain на macOS, DPAPI на Windows). Отозвать доступ можно в приложении на экране профиля
или на [myaccount.google.com/permissions](https://myaccount.google.com/permissions).
