# Установка, подключение и сборка

## Готовый установщик

Собери его локально (см. ниже) или возьми артефакты из вкладки **Actions** в GitHub — workflow `build` собирает `.dmg` для macOS и `.exe` для Windows.

**macOS.** Открой `.dmg`, перетащи Figma Analytics в Applications. Сборка не подписана Apple ID, поэтому при первом запуске: правый клик по приложению → **Открыть** → **Открыть**. Если macOS всё равно блокирует: Системные настройки → Конфиденциальность и безопасность → «Всё равно открыть».

**Windows.** Запусти `Figma Analytics Setup x.y.z.exe`. SmartScreen покажет предупреждение о неизвестном издателе: **Подробнее** → **Выполнить в любом случае**.

## Из исходников

Нужен Node.js 20+ и npm.

```bash
git clone https://github.com/egorovdnikita/figma-analytics.git
cd figma-analytics
npm install
npm run dev
```

`npm run dev` поднимает Vite и открывает окно Electron с hot reload.

## Подключение Figma

Нужен personal access token: **Figma → Settings → Security → Personal access tokens**. Достаточно прав на чтение (File content). Токен вставляется на экране подключения и хранится только на этом компьютере, зашифрованный (подробности — в [приватности](privacy.md)).

Дальше добавь команды, за которыми хочешь следить. Идентификатор берётся из адреса команды в Figma — можно вставить ссылку целиком:

```
https://www.figma.com/files/team/all-projects
```

После этого — **Синхронизировать пространство** (кнопка в разделе или `⌘K`). Первый проход самый долгий: выкачивается вся доступная история версий и все комментарии по каждому файлу. Последующие синки инкрементальные и идут заметно быстрее.

## Подключение Google

Google нужен только для входа: приложение запрашивает три scope профиля — `openid`, `email`, `profile` — и не читает ни календарь, ни почту, ни диск. Ходит оно в Google напрямую, поэтому нужен собственный OAuth-клиент. Подробная инструкция: [google-setup.md](google-setup.md).

Коротко:

1. [Google Cloud Console](https://console.cloud.google.com/) → новый проект.
2. **OAuth consent screen** → External → заполни поля → добавь свой Gmail в **Test users**.
3. **Credentials → Create credentials → OAuth client ID → Desktop app**.
4. Client ID и Client Secret вставь в приложение на первом экране — или положи в `.env`:

```bash
cp .env.example .env
```

```
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=GOCSPX-...
```

Дальше в приложении — **Войти через Google**. Откроется системный браузер, после подтверждения вкладка сообщит «Готово», и можно возвращаться в Figma Analytics.

## Сборка установщиков

```bash
npm run dist:mac    # .dmg (arm64 + x64)
npm run dist:win    # .exe (NSIS, x64 + arm64)
npm run dist        # текущая платформа
npm run pack        # распакованная сборка без установщика, для проверки
```

Поставить собранное на этот Mac:

```bash
npm run update:mac   # собрать и обновить установленное приложение
npm run install:mac  # только обновить, без пересборки
```

Обновление идёт поверх существующего бандла (`rsync`), а не «удалить и скопировать заново»: для macOS новый бандл на том же месте — другое приложение, из-за чего Dock терял запись, LaunchServices копил регистрации, а иконка бралась из кэша прежней сборки. Скрипт заодно убирает из базы промежуточные копии из папки сборки и обновляет кэш иконок.

Готовые файлы появятся в `release.noindex/`; суффикс нужен, чтобы Spotlight не индексировал промежуточные `.app` внутри и они не всплывали в поиске рядом с установленным приложением. Windows-сборку нужно собирать на Windows, macOS-сборку — на macOS (или через GitHub Actions, workflow уже в репозитории).

На Apple Silicon `.app` дополнительно подписывается ad-hoc хуком [`build/afterPack.cjs`](../build/afterPack.cjs) — без этого неподписанная arm64-сборка считается «повреждённой». Настоящей подписи Apple Developer ID у сборки нет, поэтому Gatekeeper при первом запуске всё равно спросит подтверждение.
