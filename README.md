# Figma Analytics

Десктопное приложение для macOS и Windows: аналитика рабочего пространства Figma и Google
Календарь в одном окне. Своего сервера нет — данные ходят только между вашим компьютером,
Figma и Google, а выкачанная история лежит в локальном кэше.

Стек: Electron 31 · React 18 · TypeScript · Vite · Tailwind CSS v3. Графики нарисованы
вручную на SVG, без chart-библиотек; из зависимостей рантайма — только React, `date-fns`,
`clsx`/`tailwind-merge`, иконки и шрифты.

## Что умеет

### Figma — аналитика пространства

Figma REST API не отдаёт «просмотры» и «время в файле», зато отдаёт историю сохранений и
обсуждения. Приложение выкачивает их по всем командам, разворачивает в единый поток событий
и считает аналитику уже поверх него.

**Событие** — это одно из пяти: сохранение версии, комментарий, ответ в обсуждении, закрытие
обсуждения, реакция эмодзи. У каждого есть автор, время, файл, проект и команда — дальше любой
разрез строится из этих полей.

**Синхронизация.** Обход идёт в три фазы с прогрессом: проекты команд → файлы проектов →
история версий и комментарии по каждому файлу. Повторный синк инкрементальный: если история
файла уже выкачана до конца, страницы листаются только до первой известной версии. Файлы
обрабатываются пулом (по умолчанию 4 параллельно), на `429` и `5xx` работает экспоненциальный
бэкофф. Списки проектов и файлов кэшируются на 3 минуты, командная библиотека — на 10.

**Разделы:**

- **Инсайты** — «пульс пространства»: сводный индекс здоровья по факторам, автоматические
  выводы по порогам (заброшенные файлы, обсуждения без ответа, концентрация, спад активности,
  ночная работа), прогноз на несколько периодов вперёд, аномальные всплески, жизненный цикл
  файлов (активен → замедляется → заморожен → мёртв), скорость ответа, признаки переработок,
  граф связей команды, удержание участников по когортам.
- **Дашборд** — активность по типам событий, число активных людей, текущий период против
  прошлого, распределение по часам суток и матрица «день недели × час», самые активные файлы,
  проекты и участники.
- **Тренды** — тренд со сглаживанием, год к году, накопленный объём, календарь активности,
  сезонность «год × месяц», изменение по типам событий, движение участников в рейтинге
  (bump-chart) и темп каждого.
- **Люди** — состав команды и вклад каждого, концентрация активности (какую долю делают
  самые активные), пары «кто с кем работает», динамика состава, карточка участника с его
  событиями, файлами и матрицей часов. Лишних людей можно скрыть из всей аналитики.
- **Обсуждения** — открыто и закрыто по периодам, кто задаёт вопросы и кто отвечает,
  реакции, файлы с накопленным долгом незакрытых комментариев.
- **Файлы** — самые нагруженные, файлы с открытыми обсуждениями, отметка о неполной истории.
  Карточка файла показывает последние сохранения и комментарии.
- **Библиотека** — состав опубликованной командной библиотеки (компоненты, наборы вариантов,
  стили) и авторы публикаций.
- **Активность** — сырая лента всех событий без агрегации, с поиском и фильтром по типам.
- **Настройки** — подключение, рабочий ритм команды, глубина и параллельность синхронизации,
  плотность интерфейса, пороги инсайтов, статистика кэша, список участников.

**Фильтры** общие для всех разделов: гранулярность (день/неделя/месяц/год) или произвольный
диапазон, команды, проекты, люди, типы событий, «только рабочие дни» и «только рабочие часы».
Набор фильтров сохраняется как пресет.

**Ещё:** командная палитра по `⌘K` (разделы, файлы, участники, запуск синка), закреплённые
файлы в сайдбаре, переключение любой карточки в таблицу значений, выгрузка всех событий в CSV.

### Календарь (Google)

- Виды: день, неделя, месяц, список (расписание на 30 дней вперёд).
- Все календари аккаунта: свои, общие, подписки. Каждый включается и выключается отдельно.
- События: создание, редактирование, удаление, перенос между календарями.
- Поля события: название, время или «весь день», календарь, повторение, место, участники,
  описание, напоминание, статус занятости, уровень доступа, цвет из палитры Google.
- Участники: список с ответами, ваш RSVP (буду / возможно / не буду) прямо из карточки.
- Поиск по событиям, индикатор текущего времени, выделение мышью для создания события,
  многодневные и повторяющиеся события, ссылка на исходное событие в Google Календаре.
- Автосинхронизация раз в 5 минут и обновление по кнопке.

### Профиль

- Аккаунт Google: имя, почта, аватар, домен, часовой пояс.
- Выданные разрешения, срок жизни access-токена, наличие refresh-токена.
- Выход и полный отзыв доступа.
- Настройки: тема, вид по умолчанию, первый день недели, формат времени, диапазон часов в сетке,
  показ выходных и отклонённых событий.
- Список всех календарей с ролями доступа, настройки, приехавшие из Google, данные о сборке.

### Интерфейс

- Светлая и тёмная тема, третий режим — следовать системе.
- Разделы приложения переключаются иконками слева: Figma, Календарь, а также заглушки
  Почты, Диска и Задач — состояние, IPC-слой и дизайн-токены под них уже общие.
- Горячие клавиши календаря: `D` день · `W` неделя · `M` месяц · `A` список · `T` сегодня ·
  `C` новое событие · `Esc` закрыть окно. Работают и в русской раскладке.
- `⌘K` / `Ctrl+K` — командная палитра в разделе Figma.

## Установка

### Вариант 1 — готовый установщик

Соберите его локально (см. ниже) или возьмите артефакты из вкладки **Actions** в GitHub —
workflow `build` собирает `.dmg` для macOS и `.exe` для Windows.

**macOS.** Откройте `.dmg`, перетащите Figma Analytics в Applications. Сборка не подписана Apple ID,
поэтому при первом запуске: правый клик по приложению → **Открыть** → **Открыть**.
Если macOS всё равно блокирует: Системные настройки → Конфиденциальность и безопасность →
«Всё равно открыть».

**Windows.** Запустите `Figma Analytics Setup x.y.z.exe`. SmartScreen покажет предупреждение о неизвестном
издателе: **Подробнее** → **Выполнить в любом случае**.

### Вариант 2 — из исходников

Нужен Node.js 20+ и npm.

```bash
git clone https://github.com/egorovdnikita/figma-analytics.git
cd figma-analytics
npm install
npm run dev
```

`npm run dev` поднимает Vite и открывает окно Electron с hot reload.

## Подключение Figma

Нужен personal access token: **Figma → Settings → Security → Personal access tokens**.
Достаточно прав на чтение (File content). Токен вставляется на экране подключения и хранится
только на этом компьютере, зашифрованный средствами ОС.

Дальше добавьте команды, за которыми хотите следить. Идентификатор берётся из адреса команды
в Figma — можно вставить ссылку целиком:

```
https://www.figma.com/files/team/all-projects
```

После этого — **Синхронизировать пространство** (кнопка в разделе или `⌘K`). Первый проход
самый долгий: выкачивается вся доступная история версий и все комментарии по каждому файлу.
Последующие синки инкрементальные и идут заметно быстрее.

## Подключение Google

Приложение ходит в Google API напрямую, поэтому нужен собственный OAuth-клиент.
Подробная инструкция: [`docs/google-setup.md`](docs/google-setup.md).

Коротко:

1. [Google Cloud Console](https://console.cloud.google.com/) → новый проект.
2. **APIs & Services → Library** → включить **Google Calendar API**.
3. **OAuth consent screen** → External → заполнить поля → добавить свой Gmail в **Test users**.
4. **Credentials → Create credentials → OAuth client ID → Desktop app**.
5. Client ID и Client Secret вставить в приложение на первом экране — или положить в `.env`:

```bash
cp .env.example .env
```

```
GOOGLE_CLIENT_ID...
GOOGLE_CLIENT_SECRET=GOCSPX-...
```

Дальше в приложении — **Войти через Google**. Откроется системный браузер, после подтверждения
вкладка сообщит «Готово», и можно возвращаться в Figma Analytics.

## Как пользоваться

| Действие | Как |
| --- | --- |
| Обновить данные Figma | «Синхронизировать пространство» в шапке раздела или `⌘K` |
| Быстро перейти к файлу или человеку | `⌘K` — палитра ищет по разделам, файлам и участникам |
| Сузить выборку | Панель фильтров: период, команды, проекты, люди, типы событий |
| Сохранить набор фильтров | В панели фильтров → сохранить пресет |
| Посмотреть цифры вместо графика | Переключатель «таблица» на карточке; поведение по умолчанию — в настройках |
| Убрать человека из аналитики | Настройки → участники, или карточка человека в разделе «Люди» |
| Выгрузить сырые события | Настройки → выгрузить CSV |
| Создать событие календаря | Кнопка «Создать событие», клавиша `C`, или выделите время мышью в сетке дня/недели |
| Создать событие на весь день | Двойной клик по дню в виде «месяц» |
| Открыть событие | Клик по событию в любом виде |
| Изменить или удалить | Открыть событие → «Изменить» / «Удалить» |
| Перенести в другой календарь | Открыть → «Изменить» → сменить календарь → «Сохранить» |
| Скрыть календарь | Чекбокс в списке календарей в сайдбаре |
| Найти событие | Поле поиска в шапке — ищет по всем видимым календарям |
| Сменить тему | Иконка луны/солнца в шапке или экран профиля |

## Сборка установщиков

```bash
npm run dist:mac    # .dmg (arm64 + x64)
npm run dist:win    # .exe (NSIS, x64 + arm64)
npm run dist        # текущая платформа
npm run pack        # распакованная сборка без установщика, для проверки
```

Готовые файлы появятся в `release/`. Windows-сборку нужно собирать на Windows,
macOS-сборку — на macOS (или через GitHub Actions, workflow уже в репозитории).

На Apple Silicon `.app` дополнительно подписывается ad-hoc хуком
[`build/afterPack.cjs`](build/afterPack.cjs) — без этого неподписанная arm64-сборка считается
«повреждённой». Настоящей подписи Apple Developer ID у сборки нет, поэтому Gatekeeper при
первом запуске всё равно спросит подтверждение.

## Приватность и безопасность

- Своего сервера у приложения нет: данные ходят только между вашим компьютером, Google и Figma.
- Токены Google и Figma шифруются через `safeStorage` (Keychain на macOS, DPAPI на Windows)
  и лежат в пользовательской папке приложения. Путь виден на экране профиля.
- Выкачанная история Figma хранится там же обычным JSON (`figma-cache.json`) — это ваши
  метаданные о файлах, а не содержимое макетов. Размер кэша и его очистка — в настройках раздела.
- Renderer не имеет доступа к токенам: `contextIsolation: true`, `nodeIntegration: false`,
  все обращения к API идут через IPC в main-процессе.
- Внешние ссылки открываются в системном браузере, навигация внутри окна запрещена.
- Отзыв доступа к Google: экран профиля → «Отозвать доступ». Отключение Figma: настройки раздела.

## Дизайн-система

Токены и компоненты интерфейса документированы в Storybook.

```bash
npm run storybook        # локально, http://localhost:6006
npm run build-storybook  # статическая сборка в storybook-static/
npm run storybook:coverage  # проверка, что у каждого компонента ui/ есть история
```

После включения GitHub Pages (Settings → Pages → Source: **GitHub Actions**) актуальная версия
доступна на **https://egorovdnikita.github.io/figma-analytics/** — деплоится автоматически при пуше
в `main` через [`.github/workflows/storybook.yml`](.github/workflows/storybook.yml), там же в CI
работает проверка покрытия историями.

- Токены (цвет, скругления, тени, типографика): `src/index.css`, `tailwind.config.ts`,
  описаны для документации в [`src/design-system/tokens.ts`](src/design-system/tokens.ts).
- Компоненты: [`src/components/ui`](src/components/ui) — по файлу на компонент,
  рядом лежит `*.stories.tsx`.
- Подробности и принципы — на странице **Введение** в самом Storybook.

Значения токенов сверены с Figma-библиотеками «Box UI | Tokens» и «Box UI | Primitives»,
но источник истины — код: CSS-переменные и Tailwind, а Storybook документирует то, что уже
есть в приложении.

## Ограничения

Честный список того, чего пока нет.

**Figma**

- Видно только то, что отдаёт REST API: сохранения версий, комментарии, реакции, библиотека.
  Просмотров, открытий файла и времени в файле в API нет — значит, нет и в аналитике.
- Синхронизация только ручная: расписания и фонового обновления нет, вебхуки не используются.
- Глубина истории на файл ограничена потолком страниц (по умолчанию 400 × 30 версий).
  Файлы, упёршиеся в потолок, помечаются как «история подгружена не полностью».
- Комментарии API отдаёт целиком, без пагинации — на очень больших файлах это заметно
  в первом синке.
- Библиотека читается на уровне команды: видны опубликованные компоненты, наборы и стили,
  но не использование их в конкретных файлах.
- Токен — personal access token конкретного человека, поэтому пространство видно ровно в тех
  границах, в которых его видит этот аккаунт.

**Календарь**

- Нет офлайн-режима и локального кэша — без сети события не покажутся.
- Нет перетаскивания событий мышью для переноса и изменения длительности.
- Редактор повторений — набор пресетов; произвольные RRULE сохраняются, но не редактируются.
- Изменение повторяющегося события применяется к конкретному экземпляру.
- Нет push-уведомлений системы и Google Meet-конференций при создании события.
- Многодневные события в виде «месяц» рисуются отдельным чипом в каждом дне, а не одной полосой.
- Часовой пояс события всегда системный.

**Общее**

- Почта, Диск и Задачи в левой панели — заглушки.
- Автообновления приложения нет: новая версия ставится вручную.
